# GNSS: 受信機・アンテナ・NTPサーバとの共用

## GNSS 受信機の選定

**ジッタ性能は要件にならない。** 方式Aは PPS エッジ間サンプル数を長時間回帰するので、
20〜30ns RMS のジッタは 1000エッジの平均で sub-ns まで落ちる。**どの世代でも過剰性能だ。**

**要件は3つで、どれもジッタとは無関係だ。**

1. **PPS/TIMEPULSE ピンがパッドに出ていること**
2. **u-blox であること。** 設計は `CFG-TP5`（fix 喪失時も TIMEPULSE を出させる）と
   `CFG-NAV5`（定置モード）に依存している。**UBX を喋らない受信機ではリスク5の
   逃げ道②が使えない**（→ [risks.md](risks.md)）
3. **QZSS（みちびき）に対応していること**（下記）

**GPSDO(GPS規正10MHz発振器)は買うな。** 方式Aは局部発振器の誤差を一次で相殺するので、
規正された10MHzを持ち込んでも得るものが何もない。数千〜数万円の無駄になる。

## 本当の要件は「屋内で PPS が出続けること」

日本の集合住宅で GNSS を屋内設置すると、衛星が捕まらないか、捕まっても4機を維持できず
測位解が落ちる。測位解が落ちると航法用受信機の TIMEPULSE は精度が落ちる(設定次第で
出続けるが局部発振器駆動になる)。ここが最大の実務リスクだ(リスク表の項目5)。

**タイミング用の NEO-M8T なら 0D (time-only) モードで衛星1機でも有効な時刻解が出る。**
これは本質的な違いだ。しかし——

> **M8T のブレイクアウト基板は $100 前後する。** 安価な航法用モジュール(1,000〜2,500円)との
> 差はおよそ1桁で、**この価格差は判断を変える。**

## 世代の選定: 段階1は **NEO-M8N**（2026-08-04 決定）

| | 世代 | 同時受信 | QZSS | 段階3(M8T)への接続 |
|---|---|---|---|---|
| NEO-6M | u-blox 6 | GPS のみ | **無し** | 世代が違う |
| NEO-7M | u-blox 7 | 実質1系統 | 有り | 世代が違う |
| **NEO-M8N** | u-blox 8 | **2系統** | 有り | **M8T と同世代** |
| NEO-M9N | u-blox 9 | 4系統 | 有り | **設定方式が変わる** |

**1. QZSS が効く。** 準天頂軌道なので日本の真上に近い高仰角に居る。この装置の最大の
未検証点は「屋内で時刻解を維持できるか」であり、**窓際で効くのは低仰角の衛星ではなく
頭の上に居る衛星だ。** QZSS は文字通りそのために存在する。
**NEO-6M は QZSS 非対応で、これが 6M を外す最大の理由。** 価格差の数百円で買えるものではない。

**2. 同時受信が窓際で効く。** 窓から見える空は狭い。**狭い空で衛星数を稼ぐ唯一の方法が
複数の測位系の同時使用だ。** 段階1が測りたいのは捕捉衛星数そのものなので、ここを削ると
測定の意味が薄くなる。

**3. M8T と同じ世代である。** `CFG-TP5`・`CFG-NAV5`・u-center の操作・配線が
**そのまま段階3へ持ち越せる。**

> **M9N は採らない。受信機としては上等だが、梯子の途中ではなく横道だ。**
> u-blox 9 は設定インタフェースがレガシーな `CFG-*` から `VALSET`/`VALGET` に
> 変わっており、**段階1で覚えたことが段階3で使えない。** さらに
> **M9N は M8T の代替にならない** — M8T の値打ちは受信性能ではなく
> **0D モード（位置既知なら衛星1機で時刻だけ解く）**であって、M9N にそれは無い。

**「NEO-M8N」を名乗る安価品には偽物・別チップの張り替えが混ざっている。**
届いたら u-center か `UBX-MON-VER` でチップとファームの版を読め。
**出品タイトルに複数のチップ名が並んでいたら疑え**（→ [open-questions.md](open-questions.md)）。

## 段階的に買う: 測ってから上げろ

**未測定のリスクに1万円の保険を先払いするのは順序が逆だ。**
M8T が要るかどうかは、**お前の家の空の見え方で決まる。それは測れば分かる。**

| 段階 | 買うもの | 目的 |
|---|---|---|
| **1. まず** | 安価な u-blox ブレイクアウト(NEO-6M / M8N クローン等、PPS ピンが出ているもの)**1,000〜2,500円** + **良いアクティブアンテナ 2,000〜3,000円** | **数日ログを取って捕捉衛星数と fix 安定性を測る** |
| **2. 判定** | — | 4機以上を安定維持できるなら**航法用で足りる。M8T 代を丸ごと節約できる** |
| **3. 必要なら** | NEO-M8T(約$100) | 1で「窓際でも苦しい」と実測されたときだけ。**そのとき初めて出費が正当化される** |

段階1の出費は 3,000〜5,500円。**これは捨てても痛くない額で、しかも M8T が必要かどうかの
答えが買える。** 情報を先に買うのが正しい。

そして本設計は**PPS の劣化に対して脆くない。** 1000エッジの回帰で平均するので単発の
ジッタは効かず、`pps_locked` が落ちた区間はフラグで捨てられる。累積位相を絶対値で
持つので欠測も復元できる。**「時々品質が落ちる」は許容できる故障モードだ。**

## 予算を割くべきはアンテナである (段階1の要点)

受信機を安く済ませるぶん、**アンテナに寄せろ。** 受信機の $70 の差より、
アンテナの設置場所の差の方が捕捉衛星数に効く。

- **アクティブアンテナ + SMA + 3〜5m ケーブル**を買い、窓際か屋外に置く。
  モジュール付属のセラミックパッチを室内に置くのが一番よくある失敗
- **「GPS/GLONASS 対応」と明記されたものを選べ。** GPS L1 は 1575.42MHz だが
  GLONASS L1 は **1598〜1606MHz** で帯域が違う。GPS 専用アンテナだと GLONASS 側が落ち、
  **M8N を選んだ理由である同時受信が無駄になる**（QZSS は L1 が GPS と同じなので
  この点の追加条件は無い）
- 受信機を **定置(stationary)モード**に設定する(航法用でも `CFG-NAV5` の dynModel で
  設定できる)。位置が固定なら測位のさまよいが TIMEPULSE の位相に乗らなくなる
- **fix を失っても TIMEPULSE を出し続ける設定にする**(`CFG-TP5` は locked / unlocked で
  別々に設定できる)。unlocked のパルスは局部発振器駆動でドリフトするが、
  `pps_locked` フラグで区別できるので**捨てるのは後段の仕事**にする
- TIMEPULSE は **UTC 先頭秒に整合**する設定にする(u-blox の既定。GPS時刻整合と混同するな)

## 中古のタイミング受信機という抜け道

M8T が必要と判明した場合、新品以外の道もある。Trimble Resolution T / Thunderbolt、
Motorola Oncore UT+ 等の**中古タイミング受信機**はオークションで数千〜1万円で出る。
位置を記憶させて単一衛星タイミングができる本格品だ。time-nuts 界の定番の節約路線。
ただし電源・アンテナ電圧・古い制御プロトコルの面倒を引き受けることになる。

参考: [NEO/LEA-M8T データシート](https://content.u-blox.com/sites/default/files/documents/NEO-LEA-M8T-FW3_DataSheet_UBX-15025193.pdf)、
[N8UR による各モジュールの実測評価](https://hamsci.org/sites/default/files/publications/2020_TAPR_DCC/N8UR_GPS_Evaluation_August2020.pdf)。
TIMEPULSE ジッタは M8N も M8T も 20〜30ns RMS 程度で**ほぼ同じ。ジッタは選定理由にならない**
(方式Aで平均されるので尚更)。

## 最大のレバレッジはアンテナである

受信機は2000〜6000円だが、**アンテナの設置場所は金で買えない。** ここに投資する。

- **アクティブアンテナ + SMA + 3〜5m ケーブル**を買い、窓際か屋外に置く。
  モジュール付属のセラミックパッチを室内に置くのが一番よくある失敗
- 受信機を **定置(stationary)モード**に設定する。位置が固定なら測位のさまよいが
  TIMEPULSE の位相に乗らなくなる
- TIMEPULSE は **UTC 先頭秒に整合**する設定にする(u-blox の既定。GPS時刻整合と混同するな)

## GNSS が fix しない場合

上記を尽くしても holdover に入ることはある。確度が落ちるので
`gnss_fix`/`pps_locked` をレコードに残し、**後段で品質を判別できるようにする。**
捨てるのではなくフラグを立てて出す(累積位相は絶対値なので欠測しても復元できる)。

## GPS由来NTPサーバとの共用 (別プロジェクト)

「GPS clock を使った NTP サーバが欲しい」という別件がある。共用できるかを整理する。

## 共用してはいけないもの: GNSSモジュール1台を2機で分ける

技術的には可能だが採らない。

- PPS は CMOS 出力なので複数負荷を駆動でき、バッファ(74LVC1G17等)で分配もできる
- NMEA は放送なので、GNSS の TX を2台の RX に並列に繋げば両方が読める
- **しかし設定コマンドを送れるのは実質1台だけ**になり、もう片方は受信機の設定を
  変えられない。0D モードや定置モードの設定権が片方に偏る
- **PPS は速いエッジなので、離れた機器へ引き回すと劣化しノイズも拾う。**
  同一筐体内でなければ成立しない
- そして**受信機は2000〜6000円**だ。ここを節約する理由が無い

**結論: 受信機は2台買え。**

## 共用すべきもの: アンテナ

**希少な資源は受信機ではなくアンテナの設置場所だ。** 窓際または屋外という位置と、
そこまでのケーブル引き回しは、金で解決できない。ここを共用する。

これはタイミングラボの標準的な構成でもある。1本の良いアンテナ →
**GNSSスプリッタ** → 複数受信機。

スプリッタの選定に一点だけ注意がある。

> **DC を1ポートだけ通過させ、他ポートは DC ブロック + 200Ω 負荷**の品を選ぶこと。
> アクティブアンテナへの給電は1台が担い、他は給電しない。**ただし DC ブロックだけだと
> 電流が流れず、受信機が「アンテナ異常」と誤検出することがある。** 200Ω のダミー負荷で
> 電流を模擬する品はこれを回避する設計になっている。

製品例: [uputronics GPS Antenna Signal Splitter (SMA)](https://store.uputronics.com/products/gps-antenna-signal-splitter-with-sma)、
[INSTOCK GPS212](https://www.instockwireless.com/gps-antenna-signal-splitter-gps212.htm)、
[GPS Source S12](https://www.gpssource.com/products/s12-gps-1x2-standard-splitter)。

## 設置場所は共用しやすい (この用途固有の利点)

**周波数モニタは家中のどのコンセントでも等価に測れる。** 系統周波数は家全体で同一なので、
設置場所の自由度が極めて高い。**だから NTP サーバの隣に置ける。**

これは重要だ。スプリッタでアンテナを共用するには2台が近接している必要があるが、
**この用途では周波数モニタ側が無条件に譲れる。** NTP サーバの置き場所を先に決め、
周波数モニタをその隣に置き、アンテナ1本を分岐すればよい。

## 共用できる残りのもの: 設定と知見

ハードウェア以外にも重なる部分がある。別件を先にやるなら、そこで得た知見が
そのまま本件に効く。

- **受信機の設定**(定置モード、TIMEPULSE の UTC 整合、`CFG-TP5`、fix喪失時の挙動)は両者で共通
- **アンテナ設置の試行錯誤**(窓際のどこなら何機捕まるか)は一度やれば済む
- **うるう秒の扱い**は両者で共通の論点。NTP 側は smear か step かの選択、
  本件は TAI/GPS時刻での内部計算(前述)

## やらないこと: Pi を第2系として並行稼働させる

**「Pi + GNSS + chrony は stratum-1 NTP サーバなのだから、同じ Pi に I2S ADC を足せば
第2系の周波数測定になる。1台で両目的が満たされる」という筋は採らない。**
Pi は**母艦の代替案**であって、二重測定は計画に無い。検証は二重測定に依存しない形で
組んである(→ [verification.md](verification.md))ので、ここで台数を増やす利得が無い。

参考として、もし将来やる気になった場合の注意だけ残す。DSP 負荷は割り込み遅延を増やし
PPS のタイムスタンプ精度を劣化させるので、後付けするなら:

1. **まず Pi を NTP サーバとしてだけ立てる**(別件の目的をそれ自体として達成する)
2. ESP32 系の周波数モニタを完成させる
3. **その後で**同じ Pi へ I2S ADC を足す。このとき DSP を割り込みコアから
   外して pin し、`chronyc tracking` の jitter が悪化しないことを確認する
4. 悪化するなら Pi をもう1台買う。**NTP の質を測定の都合で犠牲にするな**

この順序なら、別プロジェクトが本プロジェクトの人質にならない。
