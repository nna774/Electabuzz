### 方式Aの隠れた利点: クロック誤差が一次で相殺する

リスク4に関して重要な性質がある。方式Aでは**商用波形と PPS を同一のサンプルクロックで
測っている**ので、クロック誤差が両方に共通に乗る。

```
測定周波数 f_meas = f_true × (fs_assumed / fs_true)
そして       fs_true = (PPSエッジ間のサンプル数) / 1秒     ← 同じクロックで数えている
```

クロックが温度でドリフトすればサンプル数も一緒に変わるので、**比を取った時点で一次の
誤差が消える。** 熱ドリフトのような遅い変動は完全に相殺され、サイクル単位の速いジッタは
平均化されて残らない。

これが「PPS を別途 GPIO でキャプチャする」方式Bに対する方式Aの本質的な優位性であり、
**水晶の質にほとんど依存しない測定器になる**という意味だ。TCXO を積む必要もない。

### 着手前に調べておくこと

- **リスク7(公開実績値)** — これは部品を買う前に調べられる。突き合わせ先が存在しないと
  外部照合の手段が無くなる。**二重測定をしないと決めたので、ここは代替が薄い**
- **リスク2(PCM1808 の HPF 仕様)** — データシートを読むだけで判定できる。ADC 選定に
  直結するので最初に潰すべき
- **買う予定の GNSS 基板が PPS ピンを出しているか** — これだけは通販ページの写真と
  ピン配で確認できる。安価なクローン基板は PPS が LED にしか繋がっておらずパッドが
  出ていない個体もある
- 上の3つ以外は、実際にハードウェアを触らないと分からない。**先に紙で潰せるものは
  紙で潰し、残りをフェーズ1〜2に集約する**のが正しい順序だ

> **M8T の 0D モード・TIMEPULSE2 は今調べる必要がない。** 段階1の実測で「窓際でも
> 衛星が足りない」と判明してから調べればよい。**買わないものの仕様を先に調べるのは
> 時間の無駄だ。**

## 注意点

- **`fs` を定数として書くな。** 「48000」は二重に信用できない(缶発振器の公差か分数分周器の
  誤差か、そもそもどちらが master かも未確定)。**最初から `TimebaseEstimator` 越しに
  「測って報告する量」として持て。** これを守れば GNSS 到着は差し替え1箇所で済み、
  破らば装置全体の書き直しになる
- **`timebase_source` を必ず記録しろ。** 1バイト省いた代償は「このデータは規正済みか」が
  永久に判別できなくなることだ。**設計書の一線がこのフィールドで守られている**
- **I2S は最初からステレオで初期化しろ。** GNSS 到着前で R ch が未接続でも同じだ。
  **ここだけが後戻りできない項目**で、モノラルで作ると PPS を繋ぐ日に DMA レイアウト・
  添字・後段の全部が変わる
- **フェーズ2(PPS でのサンプルレート同定)は確度の分岐点だが、着手の分岐点ではない。**
  ここが ppb 級に落ちなければ系統時刻偏差は ppb 級にならないが、
  **`NtpTimebase` で 1ppm 級のデータは取れているので装置は止まらない**
- **`Batch` からワイヤ形式の知識を抜け。** レコード長固定と offset 20 への書き戻しの2箇所。
  抜けば共有ライブラリとして真にドメイン中立になり、Electabuzz は独自ヘッダを自由に設計できる
- **`batch-uplink` はタグで pin しろ。ブランチ追従にするな。** これが独立レポ構成における唯一の
  落とし穴だ。ブランチ追従にすると Electabuzz のための変更が地震計の次回ビルドで黙って混入し、
  **結合が不可視になる**。単一レポより悪い壊れ方をする
- **切り出しと一般化を同時にやるな。** 一般化は**検証環境が揃っている側**(Namazu)で先に済ませ、
  出来上がったものをバイト等価に移す。混ぜると実機の異常を切り分けられなくなる
- **`batch-uplink` に入れるのは4+3モジュールだけに絞れ。** `wire.py` や `events.py` を入れた瞬間に
  地震ドメインが流入し、共有ライブラリとしての価値が消える
- **NamazuHaUrokoGaNai の `terraform/` には apply しない。** Electabuzz は独立 state に閉じる。
  これで `aws_s3_bucket_notification` の単一リソース制約(1バケット1つ。既存の
  [s3.tf:31-41](https://github.com/nna774/NamazuHaUrokoGaNai/blob/master/terraform/s3.tf#L31-L41) を黙って上書きしうる)を
  踏む可能性そのものが消える
- 累積位相を**絶対値**で持て。`main.cpp:113-119` のバッチ破棄経路があるので、差分保存だと
  積分が永久に狂う
- 商用波形の THD は数%あり時刻変動する。ゼロクロス方式を採らない理由がここにある
- 日本の系統時刻偏差は制御で有界。数十秒発散したら測定側のバグを疑う。まず
  `pps_residual_ns` を見ろ
- 積算値は絶対値でなく「観測開始時点を原点とした相対値」。グラフの縦軸に明示する
