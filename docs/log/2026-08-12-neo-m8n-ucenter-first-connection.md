# NEO-M8Nをu-centorに繋ぎ、アンテナ到着前にMON-VERで本物と確認した

## u-centorへの書き込みにアンテナは要らない

u-centorが喋る相手はGNSSモジュール本体であって、UBXコマンドの送受信・`CFG-*`の
書き込みはモジュールがUART/USBで生きてさえいれば成立する。アンテナが要るのは
衛星を捕まえてfixを得る段になってから。**ただし書き込んだ設定(`CFG-TP5`の
TIMEPULSE挙動等)が実際に効いているかどうかの確認はアンテナ到着後でないとできない**
——今できるのは設定を流し込む・モジュールの素性を確認する作業までと切り分けた。

## 安価なNEO-M8Nブレイクアウト基板はUSBを持たない

手元の基板はTXD/RXD/GND/VCCのUARTピンのみでUSBが無く、PCと繋ぐには
**USB-UART変換アダプタ(いわゆる「USB to TTL」)が別途要る**。[docs/bom.md](../bom.md)に
この部品が載っていなかった漏れに気づいた(未反映のまま。要追記)。

## USB-TTLアダプタの電圧レベルは要確認、ジャンパ無しの個体は特に注意

安価なUSB-TTL変換アダプタ(CH340/CP2102系)には「3V3/5V」切り替えのジャンパがあり、
これが電源出力ピンだけでなくTXD/RXDの信号電圧レベルも一緒に切り替える機種がある。
ジャンパが無い固定タイプの場合、3V3ピンが単に別レギュレータからの電源供給専用で、
TXD/RXDの信号自体はチップのVDD(USBの5V)のまま出ている個体もあり得るため、
NEO-M8Nの3.3Vロジックへ直結すると壊す恐れがある——という注意点を整理した。

今回入手した個体は熱収縮チューブでジャンパの有無が確認できない状態だったため、
DMMでTXDピンのアイドル電圧を事前に測ってから繋ぐことを提案したが、実際には
確認前に接続された。**結果として壊れず、後段のu-centor疎通確認も問題なく通った**
(電圧を測って安全側を確認する手順自体は今後も有効な注意点として残す)。

## UBX-MON-VERで実物を確認: 本物のu-blox M8世代シリコンと判断できた

u-centorの `View > Messages View > UBX > MON > VER` で読んだ内容
(スクリーンショット: https://gyazo.com/1a30c1c5d2a31f8141ff2f41030b6fd4):

- `ROM CORE 3.01 (107888)`
- `FWVER=SPG 3.01`
- `PROTVER=18.00`
- 対応コンステレーション: `GPS;GLO;BDS` + `QZSS`

`PROTVER=18.00`はu-blox M8世代固有のプロトコルバージョンで、ファーム文字列を
偽装しただけでは出せない(NEO-6世代なら別のプロトコルバージョンになる)。
[open-questions.md](../open-questions.md)に記録していた懸念——「発注したNEO-M8Nは
天面にu-bloxロゴが見えず、SKU内部名も『NEO-8N』(実在しない型番)だった」——
はこれで解消し、**本物のu-blox M8世代チップと判断してよい**。

さらにu-blox公式のリリースノート等をWeb検索で確認したところ、`SPG 3.01`は
2016年1月リリースの、NEO-M8N向けStandard Precision GNSSファームとして**現在も
最新かつ最終の版**だった(Galileo/GAGAN対応・Beidou受信改善・省電力化が
主な変更点。これより新しいSPG系は出ていない)。**つまり手元の個体は既に最新
ファームで出荷されており、ファームウェアアップデートをかける余地は無い。**

## MON-HWの「Antenna State: OK」は鵜呑みにできないと分かった

同じくMON-HW(スクリーンショット: https://gyazo.com/5bf1aafb554d9824e564370f0a530a6b)を
見ると、アンテナ未接続にも関わらず `Antenna State Status: OK` /
`Antenna Power Status: ON` と表示された。ピン設定表を見ると、アンテナ検出に
対応するはずのANT_SHORT_N(PIO15)・ANT_SWITCH_N(PIO16)が専用ペリフェラルではなく
単なる`PIO_IN`/`PIO_OUT`になっており、**この基板ではアンテナ検出回路が実際には
配線されておらず、デフォルト値をそのまま返しているだけ**と判断した。

信頼できたのは同じ画面の`Jamming Status`欄の注記
`Unknown (Disabled/uninitialized or antenna disconnect)`の方で、こちらは
現状(アンテナ未接続)と整合していた。**このモジュールでは「Antenna State: OK」を
アンテナ接続の証拠として使えない**——アンテナ到着後の確認では、この表示ではなく
実際にfixするかどうかで判断すること。
