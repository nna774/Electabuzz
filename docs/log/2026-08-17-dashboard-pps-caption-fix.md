# dashboardの「PPS未着」キャプションを修正、ついでにクラウド着弾確認の完了に気づく

## 経緯

`dashboard/index.html` の周波数グラフ直下の説明文が「PPS未着のためGNSS品質ではなく
NTP品質」という、PPSハードウェアがまだ配線・実装されていなかった頃の記述のまま残って
いた。フェーズ2は2026-08-15に実配線・初回ロックに成功しており（残差30ns/s。
[docs/log/2026-08-15-phase2-pps-first-lock.md](2026-08-15-phase2-pps-first-lock.md)）、
「PPSが未着」という表現はもう実態と合わない。

## 訂正1回目: まだ不正確だった

最初は「PPSロック自体は実機で成功しているが、soak確認・クラウド着弾確認がまだのため、
クラウドに届いているのは今のところNTP品質のデータのみ」と書き換えた。これは
`docs/progress.md`・`CLAUDE.md`(リポジトリ直下)の「残るのはsoak確認・クラウド着弾確認」
という記述をそのまま踏襲した内容だった。

## 訂正2回目: クラウド着弾確認は実は完了済みだった

ユーザーから「2はもう来てるはず、実装した後に確認した気がする」と指摘を受け、実機の
API(`https://d3ef4geoj1wkux.cloudfront.net`)を直接curlで叩いて確認した。

```
curl -s ".../recent?minutes=30" # → timebase_source は直近30分すべて "PPS_NTP"
                                 #   latest: tb_residual_ns=0, is_disciplined=true
curl -s ".../devices"           # → device_id=1, staleness_s=3.4s（生きている）
```

**クラウド着弾確認は既に完了していた。** `docs/progress.md`・`CLAUDE.md`の「次にやる
こと」リストの更新が実装作業に追いついていなかったのが原因——おそらく2026-08-15の
フェーズ2実装直後にクラウド着弾自体は確認していたが、ドキュメント側の「残タスク」欄を
それに合わせて更新し忘れていた。

## 結論

- dashboardのキャプションは「PPSロックとクラウドへの`PPS_NTP`品質データ着弾はどちらも
  確認済み。残るのは長時間soak確認のみ」に書き直した。時刻偏差の絶対値表示機能自体は
  まだ未実装なので、その一文は残した
- フェーズ2の残タスクは**長時間soak確認のみ**に縮んだ
- 設計判断の変更はなし。ドキュメントの「現在の状態」記述を実態に追いつかせただけ
