# 2026-08-04 `NtpTimebase` を書いた — 母艦が確定し、ADC 無しで時間基準を測り始められる

母艦の現物が **ESP32-S3-WROOM-1 N16R8** に確定した。`firmware/platformio.ini` を置き、
`firmware/lib/Timebase/`（`TimebaseEstimator` / `NtpTimebase` / `MeasuringSntp`）と
フェーズ1.5 の soak スケッチ `firmware/src/main.cpp` を書いた。
**回帰は Arduino に依存しないのでホストの g++ でテストが走る**（26件、緑）。

## 決めたこと

### `residual_ns` の意味を確定した

**「回帰の傾きの 1σ を ns/s に直したもの」**、つまり実質 ppb である。
[timebase.md](../timebase.md) がダッシュボードに `±(tb_residual_ns × 経過時間)` を
描かせている以上、整合する定義はこれしかない。**経路のノイズそのものではない**
（経路ノイズは観測数と時間幅で割り算されて初めて確度になる）。

経路ノイズの方も見たいので `fitRmsNs()` として別に出したが、**ワイヤ形式には載せない。**
1バイトも足さずに済むし、後段が必要としていない。

### 不変条件をインタフェースの実装で守る

観測が 8点かつ 600秒に満たないうちは `source()` が `kNominal` を返し、
`fsMicroHz()` は**公称値をそのまま返す**。

ここが本質だ。`source` に `NOMINAL` と書いておけば十分だと思っていたが、
**中途半端な回帰の結果を `fs` として出したら、下流は `source` を見ずに信じる。**
「測れなかった区間を測れたように見せるな」は、**フラグの正しさではなく
数値を出さないことで守る**方が確実だ。

600秒という下限は「使ってよいか」であって「十分か」ではない。
**十分かは `residualNs()` が正直に答える。**

### 標本の捨てかたを4条件に決め、捨てた数を見えるようにした

往復遅延の絶対上限（150ms）/ 実測最小の3倍 / サーバ時刻の非単調 / 回帰からの 5σ 外れ。
**自前の SNTP にした最大の利点が「往復遅延が見えること」**で、lwIP の SNTP は見せない。

最小往復遅延は観測ごとに 1/64 ずつ上へ緩める。**まぐれで小さい値を1回引いただけで
以後すべて弾く**という詰まり方が、放っておくと数日走らせた後に判明する種類の事故だからだ。

そして**捨てた総数を `rejectedCount()` で出す。** 黙って捨てると経路の劣化に気づけない。
`reset()` でもこの数は 0 に戻さない。

### ティックが逆行したら積み直す

ティック源が切れたということなので、**セッション境界で線を繋がない。**
CLAUDE.md の不変条件そのものを、回帰の側で機械的に守る。

### 回帰は Welford + 公称ぶんの detrend

`Σx·Σy` 形の正規方程式は長時間で有効数字が消える。さらに `y` から公称ぶんを引いて
「公称からのずれ」にすると、傾きが 100ppm でも 100 ticks/s 程度に収まり、
30日回しても残差平方和の桁が潰れない。`fs = nominal + slope` の形で書けるのも同じ理由だ。

### PSRAM は有効化しない

要らない。1バッチ 424B で、**I2S の DMA バッファは内蔵 SRAM に置く必要がある。**
有効化しても速くも大きくもならず、置き場所を間違える余地が増えるだけである。

## 分かったこと

### N16R8 では `GPIO 33 〜 37` が使えない

モジュール内部で octal PSRAM のダイに配線されている。**PSRAM をソフトウェアで
有効化するかどうかとは無関係**で、配線は物理的に存在する。
ピンヘッダには出ていて何事もなく刺さってしまう。

**S3 を採った理由は「MCLK を好きなピンに出せること」だった**（[hardware.md](../hardware.md)）。
その自由度が実際には 33〜37 のぶんだけ狭い。結論は覆らないが、
**I2S のピンを割り当てる日に知っていないと踏む。**

### PlatformIO の `esp32-s3-devkitc-1` は N8 の定義

8MB・PSRAM 無しである。16MB を明示しないとパーティション表が 8MB のまま作られ、
**後半 8MB が黙って死ぬ。**

### この soak が測るのは ESP32 の水晶であって、`fs` ではない

`esp_timer` のティック源は ESP32 の 40MHz 水晶だ。
**I2S の MCLK を ESP32 から出す構成ならこの水晶が `fs` を決めるので結果はそのまま効くが、
PCM1808 モジュールの缶発振器が master になる構成では効かない。**
どちらが master かはまだ決まっていない（リスク10）。

つまり**リスク10 は片方しか埋まらない。** それでも走らせる価値は落ちない。
`NtpTimebase` の実装と回帰の正しさ、`MeasuringSntp` の経路、`residual_ns` の実際の値、
そして水晶の温度相関 — **PCM1808 が来た日に確かめ直す必要があるのは `fs` の出自だけ**に
絞り込める。

## 次に何が可能になったか

- **母艦を挿して焼けば soak が始まる。** 数日で手元の水晶の実 ppm と温度相関が出る
- **PCM1808 が来たら `ticksNow()` を I2S の累積サンプル数に、`kTickNominalMicroHz` を
  48000 系に差し替えるだけ。** `NtpTimebase` は1行も変わらない。
  **ティック源非依存に作ったのはこのためで、この soak は捨て仕事にならない**
- `ingest` Lambda（タスクB）は相変わらずハードウェア不要で、待ち時間に書ける
