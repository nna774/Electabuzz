# 2026-08-04 フェーズ1.5 の soak が実機で走り出した

前段（[2026-08-04-ntp-timebase.md](2026-08-04-ntp-timebase.md)）でコードは書き終えて
ビルドも通っていた。この回でやったのは**焼いて走らせること**だけだが、
実機に繋いで初めて分かったことが2つある。

## 分かったこと

### 1. pyserial は既定で DTR/RTS を立ててポートを開く

最初の捕捉で**一文字も出てこなかった。** 基板は正常で、読み手が原因だった。

ESP32 の自動リセット回路は DTR と DTS の2本で EN と IO0 を叩く。素直に開くと
基板を握ったまま黙る。**開く前に両方を落とせば出る。** `tools/soak_capture.py` に
閉じ込めた。

**さらに macOS では、それでも open の瞬間に基板がリセットされる**
（実測で毎回 `rst:0x1 (POWERON)` が出る）。ドライバが open 時点で立ててしまうので
pyserial 側から先回りできない。つまり**接続のたびに `NtpTimebase` の回帰は
ゼロから積み直しになる。**

これは受け入れる。ppm の推定は数時間で十分な精度に達するので、
**区間が切れても各区間ごとに ppm が出る**。切れ目は CSV 中の
`# capture: attached` と起動バナーで判別できる。**繋ぎ直しを避けるのは運用側の話**で、
設計を変えて解く問題ではない。

`pio device monitor` を使わない理由もここにある（tty 無しから回したい、という
事情も合わせて）。

### 2. 母艦のシリアルポートは UART ブリッジ側だった

手元の個体は `0x1A86:0x55D3`（WCH CH343）で、macOS には `/dev/cu.usbmodem*` として
見える。**名前は native USB と紛らわしいが UART ブリッジである。**
`s3-usbcdc` 環境（`-DARDUINO_USB_CDC_ON_BOOT=1`）は要らなかった。
残してあるのは、ネイティブ USB 側に挿し替えた日のためだ。

## 確認できたこと

起動バナーが `flash=16MB` を返した。**`platformio.ini` の 16MB 上書きが実機で
効いている**ということで、N8 の board 定義を潰した判断が裏取りできた。
これを怠ると上半分が黙って使われないままになる。

不変条件も設計どおりに見えている。観測が 8点・600秒に満たないうちは
`source` 列が `NOMINAL`、`resid_ns` が `4294967295`（未知は「最悪」で申告）、
`ppm` が `0.0000`（公称値をそのまま返している）。**中途半端な回帰の結果を
「測った値」として出さない**という一線が、CSV の見た目にそのまま出る。

## 次に何が可能になったか

数日走らせれば手元の水晶の実 ppm と温度相関、および `residual_ns` の実際の値が
取れる。**ただしこの soak が測るのは ESP32 の 40MHz 水晶であって `fs` ではない。**
リスク10 は片方しか埋まらない（→ [risks.md](../risks.md)）。

生ログは `soak/` に置き gitignore する。**結論はドキュメント側に書く**ので、
CSV そのものをレポに残す必要はない。
