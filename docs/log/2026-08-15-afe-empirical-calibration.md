# AFE換算(`v_rms_mv`)を経験係数で校正する

## 何をしたか

`firmware/src/config.h`に`kAdcAmplitudeCalFactor = 1.182`を追加し、
`computeVRmsMv()`内の「ADCコード→node A電圧」変換(`nodeAPeakVolts`)に
この係数を掛けるようにした。**分圧計算(`kAfeDividerRatio`)には掛けない**
——後述の通り、そちらは実測で無罪と確定したため。

## なぜやったか

トランス巻数比の実測(PR #45、[log/2026-08-15-trans-turns-ratio-simultaneous-measurement.md](2026-08-15-trans-turns-ratio-simultaneous-measurement.md))で、
DMMがトランス二次側を**10.21V**(壁側102.8〜102.9V、実回路稼働中)と読んだ。
ほぼ同じ時間帯(17:55〜17:59 JST)にfirmwareが送信していた`v_rms_mv`の生値
(校正前の理論式のまま)は5バッチ平均で**約8480mV**——比にして約1.204倍、
17〜20%の系統的な食い違いがあった。

`hardware.md`が事前に警告していた無負荷↔全負荷の電圧降下(最大25〜27%)を
最初に疑ったが、DMM測定時もfirmware計測時もESP32・AFEの実回路は稼働中で
条件は揃っていたとユーザーに確認が取れたため、この仮説は棄却した。

## 何が分かったか

最初は「どの定数が具体的にずれているか特定せず、実測との比を単一の経験係数
として末尾に掛ける」設計で着手した(校正係数1.204)。だが「理論値0.49Vのところ
node A実測0.577Vはけっこう高くないか」という指摘を受け、**容疑者を1つずつ
実測で消去する**方向に切り替えた。

1. **分圧網(R1/R2/ADC入力インピーダンス)** — node A(PCM1808のL IN、分圧後・
   GND基準)をDMMのACレンジで直接実測し、**0.577V**を得た。DMM実測の二次側
   (10.21V、PR #45)× 理論分圧比(`kAfeDividerRatio`≒0.0576)から予測される
   node Aは0.588V——ズレは**1.8%**で、抵抗の公称誤差の範囲に収まる。
   **無罪と確定。** (この比較は2つの独立したDMM実測同士の突き合わせで、
   firmwareのADC変換を経由しない)
2. **VCCの経年ドリフト** — `kAdcVccVolts`は2026-08-05の実測1点(4.84V)を
   使っていた。2026-08-15にDCレンジで再実測し、**4.83V**を得た。ほぼ同じ。
   **無罪と確定。**
3. **Goertzelの振幅推定式**(`ampCode = 2×magnitude/N`) — 合成正弦波を使った
   ホストテストで振幅既知の入力に対し1%以内の一致を確認済み
   (`firmware/lib/Goertzel/test/test_goertzel.cpp`)。**無罪。**

3つを消去した結果、残る容疑は**「フルスケールコード(2^23)が本当に
0.6×VCCのVpp入力レンジに対応するか」というデータシートの解釈そのもの**に
絞られた。firmwareが独自に計算していたnode A(0.488V、校正前のADC変換式が
出す値)とDMM実測のnode A(0.577V)を比べると比は**1.182**——これが
更新後の校正係数の根拠になっている(旧係数1.204は、分圧網の1.8%のズレも
一緒くたに含んでいた値だった)。

## 何が覆ったか

- 校正係数を1.204→**1.182**に修正し、掛ける場所も「secondaryRmsMv全体」から
  「nodeAPeakVolts(ADCコード→node A電圧の変換)」に移した。分圧計算自体は
  実測で無罪と確定したので理論式のまま触っていない
- 定数名を`kAfeEmpiricalCalFactor`→`kAdcAmplitudeCalFactor`に変更し、
  校正が局在する場所を名前でも示すようにした
- `config.h`の「用途には十分だが絶対確度を主張しない」という注記は、
  容疑の絞り込みが進んだ分だけ具体性を増した——ただしフルスケール解釈の
  最終確認(データシート再読 or オシロでの波形直接確認)はまだ済んでいない

## 次に何が可能になったか

`v_rms_mv`が実測に近い値を返すようになったので、ダッシュボードでの
壁側電圧概算表示(`v_rms_mv × 巻数比10.08`)を実装しても、既知の系統誤差を
そのまま乗せることにはならない。**ただし1点校正でしかない**——複数回・
複数条件(負荷変動・気温)での再検証はまだ。この係数を実機へOTAで投入し、
再度DMMと突き合わせて残差を確認するのが次の一手。余裕があれば、PCM1808の
データシートで「0.6×VCC Vpp」がheadroom込みの公称値か物理クリップ点かを
確認すれば、最後の容疑も晴らせる。
