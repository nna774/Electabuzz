# 2026-08-03: フェーズ0（紙の調査）— 外部照合先の確保と先行実装の判明

ハードウェア不要・費用ゼロの調査。主要2件が決着し、先行実装の構成も判明した。

## 覆ったこと: 想定していた外部参照は存在しなかった

**東電PG / OCCTO は「系統周波数」の実績を公開していない。**
公開しているのはでんき予報の**需給実績**（電力使用状況・エリア需給、CSV）であって、
周波数ではない。系統情報公表制度で出るのも予想潮流等。

## 決めたこと: 個人運営の計測サイトを照合先にする

- **[powerk95](https://powerk95.net/50Hz/)** — **東日本50Hz系統**の周波数を実時間公開。
  **周波数・RoCoF・時差**を出し、日次グラフと**CSV履歴**がある。60Hz版の姉妹サイトあり。
  閾値超過のブラウザ通知、リプレイ機能、本日の最大/最小の記録も持つ
- [power.f5.si](http://www.power.f5.si/) — 電源周波数変動の公開。アラーム通知付き

**外部照合先は確保できた。** ただし相手も個人の測定なので「真値との一致」ではなく
「独立した2系が一致するか」の検証になる。絶対確度は GNSS TIMEPULSE2 自己校正が担保する。

**さらにこれで目標イメージが確定した: powerk95 のようなサイト。**
実時間の周波数・RoCoF・時差、日次の最大/最小、閾値通知、履歴のリプレイ。
ダッシュボード要件はここを参照する。

## 決めたこと: PCM1808 の HPF はデジタルなのでリスクが消滅した

データシートは「delta-sigma modulator with 64-times oversampling +
**digital decimation filter and high-pass filter** that removes the dc component」と
記述しており、デシメーションフィルタと同じデジタル信号路にある。

**デジタルであることが決定的だ。係数が固定なので温度で位相がドリフトしない。**
リスク項目2（位相の熱ドリフト）は**原理的に発生しない**。

- デジタルフィルタの諸元はすべて fs で正規化されている（pass band 0.454 fs 等）。
  HPF のコーナーも fs 比のはずで、fs は GPS で規正して正確に知るので位相シフトは既知の定数になる
- 仮にコーナーが 2.7Hz でも 50Hz での位相は arctan(2.7/50) = **3.1°、しかも定数**。
  定数位相は時間微分でゼロになるので瞬時周波数に効かない
- **外付けSAR ADC への退避は不要になった**

## 判明したこと: 先行実装（W53SA 氏）の構成

**友人 = W53SA 氏。[記事](https://www2.hatenadiary.jp/entry/2022/04/12/freqWatch)（2022-04）で
構成が判明した。** 東西の両方を測定している。

**ゼロクロス検出・時間基準なし・絶対確度 ±10ppm・時刻偏差は出していない。**

### 照合の位置づけが変わった

相手は無基準なので**絶対値の照合には使えない**。使えるのは**周波数変動の「形」と
イベントの一致**である。ΔTE は必ずランプになり、その傾きは
**相手の水晶オフセットの実測値**として読む。

これは悪い知らせではない。**絶対確度の担保は TP2 自己校正が負い、この照合が負うのは
「系統の実挙動を捉えているか」であって確度ではない。役割を分けられた。**

### 本設計の判断が二つ裏付けられた

1. **ACアダプタを絶縁センサに使う判断。** 経験のある人間が独立に同じ選択をしている
2. **MCPWM input capture（= 本設計の方式B）に動いている先行例がある。**
   方式A が駄目でも退避先が実在すると分かった

### そして GNSS 規正に投資する理由が実例になった

**「時刻偏差を出していない」のは選択ではなく出せないからだ。**
無基準では 0.86秒/日 の偽の偏差が積算される。系統時刻偏差の実変動が数秒である以上、
意味を成さない。**本設計が GNSS 規正に金と手間をかける理由が、目の前に実例として存在している。**
