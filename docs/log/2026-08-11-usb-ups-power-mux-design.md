# USB無停電化(乾電池バックアップ)の回路案検討

## 背景

別セッションで、装置本体(母艦ESP32-S3)へのUSB給電が途絶えたら乾電池から無瞬断で
給電を引き継ぎ、乾電池給電中であることをGPIOへフラグ出力する回路が検討され、
その概要が本セッションに共有された。これは [docs/hardware.md](../hardware.md) の
「電源」節にすでにある**未詳細化の計画項目**

> 周波数データが最も価値を持つのは系統異常時、つまり停電の前後である。装置が対象と
> 一緒に落ちるとその瞬間を取り逃がす。パススルー対応モバイルバッテリーか小型UPSを挟む。

の「小型UPSを挟む」を具体化するものにあたる。市販パススルーモバイルバッテリーとの
違いは、**「今どちらの電源で動いているか」を機械可読なフラグとして出せる点**——
既存計画が要求する「停電検出時は明示記録」を、追加の検出回路無しで満たせる。

## 提案された構成

```
USB入力 ──┐
          ├─→ 電源マルチプレクサIC(自動切替) ──→ USB出力(母艦へ)
乾電池 → 昇圧 ┘        │
                    STAT ──→ (停電フラグ用GPIO)
```

- TI の電源マルチプレクサIC(TPS2113A系)で2系統入力の自動切替を行う
- 乾電池(単三3本直列など)は電圧が不安定(消耗で4Vを切る)なので、昇圧コンバータで
  5Vへ整えてからマルチプレクサの第2入力へ入れる
- マルチプレクサのSTATピンをそのまま停電フラグとして使う

## 判断: 方向性は妥当。ただし本採用前に詰める点が3つある

**電源マルチプレクサIC(自動切替・逆流防止・ステータス出力付き)という部品カテゴリを
選んだこと自体は正しい。** ダイオードORを自分で組むより保護・切替速度の面で優れており、
「USB→USBパススルー+乾電池バックアップ+ステータスフラグ」という要求にちょうど合う
製品カテゴリがTIに実在する。ゼロから設計するよりこちらを使う判断は妥当。

以下は回路図確定前に潰すべき点(未検証):

1. **昇圧コンバータが本当に要るか、マルチプレクサICの入力電圧下限を先に確認しろ。**
   この種のICは「USB(5V) + Li-ion(〜4.2V以下)」のバックアップを主用途にしており、
   入力電圧レンジが2.5V付近まで許容する型番がある。単三3本直列(新品4.5V、消耗末期でも
   2.7〜3V程度までは実用域)がその範囲に収まるなら、**昇圧コンバータ自体を省略できる**。
   これは実装がシンプルになるだけでなく、次の項目も同時に解決する。

2. **昇圧コンバータを常時通電する設計だと、無停電待機中に乾電池を静かに消耗し続ける。**
   マルチプレクサは「今刺さっている方の電源を選ぶ」だけなので、USB給電中でも
   バックアップ側の5Vは常に用意しておく必要がある(でなければ切替の瞬間に電圧が
   まだ立ち上がっていない)。つまり昇圧コンバータはUSB給電中も止められず、
   その静止消費電流(数百µA〜数mAのICが多い)が何ヶ月もの待機期間ずっと乾電池を
   削り続ける。**「いざという時のための乾電池が、使われる前に自然放電で切れていた」
   という本末転倒が起こり得る。** 昇圧が本当に必要なら、無負荷時静止電流が
   一桁µA台の低Iq品を選ぶこと。前項の「昇圧を省略できないか」を先に確認する理由は
   ここにもある。

3. **乾電池はアルカリではなくリチウム一次電池を検討する価値がある。** この装置は
   実際に停電が起きるまで乾電池側が一度も使われない「無停電の待機用途」。
   アルカリは自己放電・液漏れのリスクがあり無交換で長期待機に向かない。
   Energizer Ultimate Lithium等のリチウム一次電池は自己放電が極めて小さく
   (公称10年超の保存寿命)、低温特性も良く、この用途に合う。

## その他の設計メモ(次の一手)

- **出力側バルクコンデンサの容量は「盛る」のではなく計算しろ。** マルチプレクサの
  切替時の電圧降下(データシートのbreak-before-make時間・出力undershoot仕様)と
  母艦側の実消費電流から `ΔV = I・Δt / C` で必要容量を出す。母艦(ESP32-S3 + GNSS +
  PCM1808)の実消費電流は [hardware.md](../hardware.md) 「電源」節に見積り(1W級)がある
- **STATピンの論理レベルをESP32のGPIO(3.3V系)に合わせて確認する。** オープンドレイン
  なら3.3V側でプルアップすればよいが、5V系プッシュプルの型番もあるため要データシート確認
- **既存の停電検出(AFE経由のv_rms低下検知)と突き合わせられる。** このICのSTATフラグと
  v_rms低下は独立した2系統の「停電っぽさ」の根拠になるので、記録時に両方残せば
  相互検証に使える(食い違えば「USB電源側だけ落ちた」等の切り分けに使える)

## 結論

**作れる。方向性(電源マルチプレクサIC + ステータスフラグ)は妥当で、
docs/hardware.md の「小型UPSを挟む」計画をこのまま具体化してよい。**
ただし部品確定(型番・入力電圧レンジ・静止電流)は未検証のままなので、
本ログは検討記録であって決定ではない。実装に進む際は上記3点をデータシートで
潰してから型番を確定させること。
