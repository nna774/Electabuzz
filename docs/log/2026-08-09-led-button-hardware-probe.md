# 母艦のLED・ボタンを実機で調査した

母艦(ESP32-S3-WROOM-1 N16R8のDevKitC-1系クローン)には、AFE用に配線した4本
(GPIO15/16/17/18)以外にもLED4個・ボタン2個が載っている。シルクにLEDの型番・ピン
表記が一切無いクローン基板だったので、机上の推測ではなく実機での能動的なテストで
正体を確定させた。使い捨ての調査用スケッチ(`firmware/src/main.cpp`を一時的に
置き換えたもの)で行い、**コミットはしていない**——正体が分かった時点で元に戻した。

## 分かったこと

| 部品 | 正体 | 制御可否 |
|---|---|---|
| 白い正方形パッケージ(ボンディングワイヤが見える) | WS2812アドレッサブルRGB LED、**GPIO48**で確定 | `neopixelWrite(48, r, g, b)`（Arduino-ESP32コア組み込み、追加ライブラリ不要）で自在に制御可能。赤→緑→青と狙った通りに変化することを実機で確認 |
| 常時点灯の橙〜赤(他LEDと同じ並びの1個) | 電源インジケータ、3V3直結 | 制御不可(想定通り) |
| 残る2個(常時点灯LEDの左隣) | **USB-UARTブリッジ(VID:PID `1A86:55D3`, WCH系)のTX/RXアクティビティ表示**。ESP32のGPIOには繋がっていない | **ファームからの直接制御は不可能。** シリアル送受信量に応じて自動点滅するだけと実機で確認した(50回連続コマンド送信中は点灯、5秒沈黙で消灯) |
| BOOTボタン | **GPIO0**。`pinMode(0, INPUT_PULLUP)`で起動完了後は普通の入力として読める | 押下・離しの両方をリアルタイムでシリアルログへ正しく出力できることを確認済み |
| RETボタン | `EN`直結のハードウェアリセット | ソフトウェアからは検出不可能。実際に3回押して`POWERON`リセットの発生を確認した |

## 調査の経緯（つまずいた点）

最初はGPIO0〜48の安全な候補（33〜37=PSRAM、26〜32=flash、43/44=コンソール、
19/20=USB、0/3/45/46=ストラップ、15〜18=I2S使用中、を除外）を750msずつ順番に
HIGHにする自動スイープで様子を見た。緑LEDがそれに同期して点滅するように見えたが、
その後BOOTボタンを押させて厳密に時刻相関を取ろうとしたところ相関が取れず、
**むしろシリアル通信の発生タイミングと一致している**という指摘をユーザーから受けた。
そこで自動スイープをやめ、シリアルコマンドで狙ったGPIOだけをHIGHに固定できる
対話式スケッチに切り替えて二分探索→最終的に「GPIO出力ではなくシリアル通信量に
反応している」ことをバーストテストで確定させた。

**教訓: 定期的な自動処理(ここではSerial.printfを伴うGPIOスイープ)と、それに近い
周期の別の現象を同時に動かすと、見た目の同期だけで誤った相関を掴みやすい。**
今回は「通信を止めても光り続けるか」という対照実験で切り分けられた。

## 副産物: 積み残し課題を1つ解消した

[open-questions.md](../open-questions.md)の「緊急再起動ボタン」の項目
（→ [2026-08-09-emergency-reboot-button-reconsidered.md](2026-08-09-emergency-reboot-button-reconsidered.md)）
が「現物で`digitalRead(0)`が反応するか確認してから着手を判断する」で止まっていたが、
今回の調査でその確認が済んだ。**BOOTボタンは押下・離しの両方を正しく検出できる。**
実装に着手するかどうかは別途優先度で判断する。
