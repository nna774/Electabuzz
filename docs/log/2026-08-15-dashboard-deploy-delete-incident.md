# ダッシュボードデプロイで`--delete`を使い、OTAバイナリを消した事故の記録

## 何をしたか

`dashboard/README.md`のデプロイ節と`docs/ota.md`のOTA配布物の節に、
「`aws s3 sync`に`--delete`を付けるな」という警告を追加した。

## なぜやったか

PR #49(v_rms_mvグラフ追加)のデプロイ作業中、手順書に無い`--delete`を
独断で足して`aws s3 sync . "s3://$BUCKET/" --delete`を実行した。ダッシュボード
用S3バケットはOTA配布物(`ota/record/<version>.bin`・`.sha256`、→
docs/ota.md 6章)と相乗りしており、ローカルの`dashboard/`ディレクトリには
`ota/`が存在しないため、配信中のファーム一式(`efa8199`・`9fedfc5`・
`351cd38`・`b521d6c-dirty`の各`.bin`/`.sha256`、計8オブジェクト)が
削除対象と判定され消えた。

バケットのバージョニングは無効(`aws s3api get-bucket-versioning`が空応答)
のため、S3側からの自動復旧はできなかった。

## 何が分かったか

- 削除されたのはいずれも当時運用上不要になっていた旧ビルドで、実害は
  無かった(ユーザー確認済み)
- 手順書(`dashboard/README.md`)自体は元々`--delete`無しの正しいコマンドを
  書いており、事故は手順書の不備ではなく手順からの逸脱が原因だった
- 「バケットが2つの用途で共有されている」という非自明な制約が、
  デプロイ手順の近くに明文化されていなかった——これが無警告での
  `--delete`追加を誘発した

## 何が覆ったか

覆っていない。

## 次に何が可能になったか

同種の事故は再発しにくくなったはず。実機のOTA挙動自体には影響していない
(`pending_ota_version`を今回のバイナリに向けていなければ、次回OTAは
`tools/publish_ota.sh`で新規ビルドを配布すれば済む)。
