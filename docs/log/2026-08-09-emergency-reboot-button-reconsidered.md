# 緊急再起動ボタン、「対応ハードウェア無し」の判断を撤回する

[前回の調査](2026-08-09-namazu-convenience-features-survey.md)で「Namazuの緊急再起動ボタンは
TFT+ボタン前提のNamazu固有機能で、Electabuzzには対応する入力デバイスが無い」と書いたが、
ユーザーから「母艦にボタンが付いている」と指摘を受けた。

## 分かったこと

母艦の購入元(AliExpress、商品ID `1005006418608267`)のページはJSで生成されるSPAで、
`WebFetch`では商品詳細(型番・搭載チップ・ボタン構成)を取得できなかった
（フッターのリンク集しか拾えない）。**型番は現物の刻印か出品ページを直接見るしかない。**

ただし`docs/progress.md`(2026-08-04)で母艦は既に**ESP32-S3-WROOM-1 N16R8**と確定しており、
[hardware.md](../hardware.md)のI2Sピン割り当て(`SCK`=GPIO16、`BCK`=GPIO17、`LRC`=GPIO18、
`OUT`=GPIO15、→ hardware.md:626-629)を踏まえると、**GPIO0は現在何にも使っていない**。

一般的なESP32-S3 DevKitC-1系クローンボードは、タクトスイッチを2つ載せているのが定番:

- **BOOT(GPIO0)**: 起動時のブートストラップピンだが、起動後は普通のGPIOとして読める。
  Namazuと同じ「長押し検出でフラグを立てる」ソフトウェア実装が成立しうる
- **RST/EN**: `EN`ピン直結のハードウェアリセット。ソフトウェアからは検出不可能——
  押した瞬間に問答無用で電源が落ちる。Namazuの「RAMキューをLittleFSへ退避してから
  再起動する」安全なシーケンスとは相容れない

**確実な判断は現物での`digitalRead(0)`テストが要る。** GPIO0はブートストラップピン
（起動時Lowならダウンロードモードに入る）なので、①押しっぱなしで起動しない
②起動完了後に読んで反応するか、の両方を実機で確認してから使うかどうか決める。

## 現在の結論（[open-questions.md](../open-questions.md)を修正）

「対応ハードウェアが無い」という前回の判断を撤回し、「BOOTボタン(GPIO0)が使える
可能性がある、現物確認待ち」という候補に差し替える。
