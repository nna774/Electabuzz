# 2026-08-04 ingest Lambda を書いた

`lambda/ingest/handler.py` と `lambda/s3keys.py`。テスト37件が緑。
**AWS には一切触らない**（S3 クライアントは偽物を差し込み、DynamoDB は
`record_batch` を差し替える）。検証したいのは「どの入力がどのキーに、
どの状態コードで落ちるか」であって boto3 の挙動ではない。

構造は Namazu の `ingest/handler.py` を踏襲した。`auth.verify()` →
`wire_gridfreq.parse()` → device_id 一致チェック → `put_object()` →
生存台帳、の流れは同じだ。**違えた3点だけ書く。**

## 決めたこと

### 1. 置き先は `series/`。`batch_uplink.s3util` を使わない

**これが一番危なかった。** あちらの `raw_key()` は `raw/` 固定で、Namazu 側の
lifecycle は `raw/` に 90日の expire を掛けている。累積位相をそこへ置くと
**永久保存のはずのデータが90日で消える**。しかも気づくのは3ヶ月後だ。

当初の設計（[batch-uplink.md](../batch-uplink.md)）は「別 prefix が要ると確定したら
v1.1.0 で `s3util` の prefix を引数化する」としていた。**これは覆した。**
prefix は保存方針そのものであって、共有ライブラリの既定に寄りかかってよい種類の
値ではない。**呼び出し側に名指しさせる方が安全**なので、`lambda/s3keys.py` に
自前で持つ。キーの形（`{device:04d}-{batch_start_us:020d}.bin`）は共有ライブラリと
同一に揃えたので、揃える価値のある部分は失われていない。

これに伴い [open-questions.md](../open-questions.md) の「S3 の prefix」を落とした。
問いではなく決定になったからだ。

### 2. CRC 不一致は隔離して 200 を返す

パーサが `WireFormatError`（読めない）と `CrcMismatch`（壊れている）を
**別の型にしてある意味が、この呼び出し側で初めて出る。**

| 事象 | 応答 | 置き先 |
|---|---|---|
| 署名不一致 | 401 | — |
| 本文の device_id が名乗りと違う | 403 | — |
| 読めない（magic 違い等） | 400 | — |
| **CRC 不一致** | **200** | **`bad/`** |

400 を返すとデバイスは同じ壊れたバッチを送り直し続け、**後続の正常なバッチが
待たされる**。捨てると壊れ方の証拠が消える。**隔離して 200 を返し、次へ進ませる。**

隔離キーには `batch_start_us` を使わない。CRC が合わないバッチのヘッダを信じると
キーが飛ぶからで、受信壁時計と本文ハッシュで組む。device も**署名検証に通った
名乗り**を使い、本文の値は信用しない。

### 3. 生存台帳はテーブル未設定なら書かない

`NAMZ_DEVICES_TABLE` が無ければ `record_batch()` を呼ばない。watchdog を立てるまで
台帳の置き場が無く、毎バッチ例外を吐かせても雑音にしかならない。
**呼んだ上での失敗を握りつぶして 200 を返す**判断（デバイスに無駄な再送をさせない）は
Namazu のまま踏襲している。

## 書かなかったもの

**`/alert` は意図的に実装していない。** 周波数側のイベント定義（逸脱・RoCoF・停電）も
通知先も未確定で、**今書くと確定した頃には作り直しになる**。JSON なので
フィールドを差し替えるだけであり、後から足す費用は小さい。

**`terraform/` も書いていない。** バケットも Function URL もまだ無いので、
zip を作っても食わせる先が無い。

## 覆らなかったこと

env の接頭辞。[batch-uplink.md](../batch-uplink.md) が既に
「`NAMZ_` のまま使い、Electabuzz は自分のスタックの値を同じ名前で渡す」と
決めていた。一度 `ELBZ_DEVICES_TABLE` → `NAMZ_DEVICES_TABLE` の shim を書いたが、
**それは決定に逆らって二重管理を作る**ので捨てた。

線引きは「**`batch_uplink` が読む変数は `NAMZ_`、こちらの独自変数は `ELBZ_`**」。
どちらが読む変数かが名前から一意に決まる。

## 次に何が可能になったか

`terraform/` を書けば ingest は着弾する。ただし**デバイス側の送信経路がまだ無い**
（`main.cpp` は soak 専用で ADC も Uploader も入っていない）ので、
**急ぐ理由は無い。** フェーズ2（PPS 同時サンプリング）が成否の分岐点である以上、
そちらが通ってからでよい。
