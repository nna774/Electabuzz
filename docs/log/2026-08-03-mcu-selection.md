# 2026-08-03: 母艦は ESP32-S3 にする — ただし S3 必須ではないと確定した

## 問い

「ESP32 の S3 が要るんだったか。Namazu の方はそこまでは要らなかった。
同じ機器が1つ余っていて、そっちの方が安いので、本当に要らないならそっちを使ってもいいか」

## 決めたこと

**この設計は ESP32-S3 を必要としていない。無印 ESP32 でも全要件を満たす。**
そのうえで、**両方が手元に余っているので S3 を採る。**

| 要件 | 無印 ESP32 | ESP32-S3 |
|---|---|---|
| I2S RX の DMA・ステレオ 48kHz | 可 | 可 |
| 単一ビン Goertzel（FPU） | 可。48kHz で約 300 kFLOP/s と桁で余る | 可 |
| 二コア分離 | 可 | 可 |
| 方式B の MCPWM capture | 可。**W53SA 氏の先行例はこちら** | 可 |
| I2S の APLL | **あり** | **無い** |
| ETM | 無い | **無い** |

**S3 を採る理由は MCLK の出力ピン、それだけだ。**

PCM1808 は SCKI を要求する。モジュールに缶発振器が載っていなければ ESP32 から MCLK を
出すことになるが、**無印 ESP32 の I2S MCLK 出力は GPIO 0 / 1 / 3 に限られる**
（ESP-IDF がエラー文字列に `"only gpio 0/1/3 are supported on esp32"` と書いている）。
GPIO0 はブートストラップピン、GPIO1/3 は UART0 の TX/RX = シリアルコンソールである。
**どれを選んでも代償がある。**

**これが効くのは、設計書が「SCKI の master は測定で決め、決めたら変えるな」としているからだ。**
無印で始めてフェーズ1.5 の実測が「ESP32-as-master の方がまし」と出たら、
GPIO0 かコンソールのどちらかを諦める袋小路に入る。**S3 なら両方の選択肢が生きたまま残る。**

## 覆ったこと（設計書に2つ誤りがあった）

調べたら、S3 について書いていた記述が二つとも間違っていた。

### 1. ESP32-S3 に ETM は無い

設計書は方式B の手段として「ESP32-S3 の GPTimer+ETM」を挙げていた。**存在しない。**

- ESP-IDF の ETM ドキュメントは **esp32c6 では存在するが esp32s3 では 404**
- `components/soc/esp32s3/include/soc/soc_caps.h` に `SOC_ETM_SUPPORTED` の定義が無い

**方式B の手段は MCPWM capture のみである。**
ただし**退避先を失ったわけではない**。MCPWM capture は無印 ESP32 にもあり
（`SOC_MCPWM_SUPPORTED 1`）、**W53SA 氏の先行例が実際に動かしているのはこれだ。**
「動いている先行例がある」という方式B の価値は無傷。

なお ESP32-S3 では `mcpwm_capture_timer_config_t::resolution_hz` が無効で、
**capture timer の分解能は APB 固定**（80MHz = 12.5ns 刻み）。PPS には十分だが、
設定できると思って書くと動かない。

### 2. ESP32-S3 の I2S は APLL を持たない

設計書は「48kHz は 160MHz 系から割り切れないが、APLL を使えばずっと近づく」と書いていた。
**APLL があるのは無印 ESP32 の方で、S3 には無い。**

- `soc/esp32s3/.../soc_caps.h`: `SOC_I2S_SUPPORTS_APLL` の定義**なし**
- `soc/esp32/.../soc_caps.h`: `#define SOC_I2S_SUPPORTS_APLL (1)`

**だが結論は変わらないし、困りもしない。** 公称値からの定数ずれは `NtpTimebase` の回帰が
そのまま吸収する（回帰は傾きを測るので `fs` が 48000 でなく 47998 でも正しく求まる）。
効くのは**安定度**だけで、分数分周（PLL_160M）と APLL のどちらが安定かは自明ではない
（APLL は fractional-N なので位相雑音が悪い可能性がある）。
**フェーズ1.5 で測って決める話であり、チップ選定の理由にはならない。**

むしろこの事実は設計の主張を補強する。**S3 では「fs はちょうど 48000」というふりが
物理的にできない。** それは正しい心構えを強制されているという意味だ。

## 次に何が可能になったか

- **チップ非依存だと分かったので、余っている無印 ESP32 を捨てなくてよい。**
  予備機・故障時の差し替え先・（将来やる気になったときの）第2系の母艦として使える。
  設計書に「S3 必須」と書いてしまうとこの選択肢が消えるので、**必須ではないと明記した**
- リスク11 として「S3 でなければ成立しない要件は存在しない」を追加。
  **逃げ道が一本増えた**

## 注意

**`NtpTimebase` の水晶特性は本番で使う個体で測れ。**
フェーズ1.5 の目的は「自分が乗る水晶の実 ppm と温度相関を知ること」なので、
**余っている別の個体で測っても本番の役に立たない。開発機と本番機を分けるな。**
