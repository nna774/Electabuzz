# powerk95との外部照合を初めて実施した(相関0.993)

## 何をしたか

[verification.md](../verification.md)「外部照合(補助)」に挙げていた
[powerk95](https://powerk95.net/50Hz/)との突き合わせを、実機稼働データで初めて実施した。

- Electabuzz側: `/recent?minutes=30` を叩き、JST 00:38:43〜01:08:43の瞬時周波数を取得
- powerk95側: 50Hz(東日本)専用ページ(`https://powerk95.net/50Hz/index.html`)の
  グラフ画面(7時間レンジ)の「CSV出力」ボタンから同時間帯の秒次CSVを取得
- 両者をJST秒でキーを揃えてinner join(共通1788点)し、相関・平均差・標準偏差を計算

## 副産物: powerk95の使い方

- **60Hz(西日本)ページがデフォルトで、50Hz(東日本)ページは別URL**
  (`/50Hz/index.html`)。60Hzページのメニュー→リンクから遷移できる
- 「データDL」タブの日次CSVダウンロードは**当日分がまだ未確定で失敗する**
  (「該当日のデータはありませんでした」)。前日以前なら取れる見込み
- 直近データが欲しい場合は、グラフ画面(7時間/1日/3日レンジ切替可)の
  「CSV出力」ボタンを使う。こちらは即座に落ちる
- ブラウザ拡張(claude-in-chrome)経由の操作だとダウンロードがサンドボックスで
  ブロックされ、ページ内のChart.jsインスタンス(`Chart.instances[0]`)から
  DOM/JS経由でデータを抜こうとしても出力の文字数制限(~1000文字)に阻まれた。
  **結局ユーザー本人がブラウザでボタンを押すのが一番早い。**
  回避策を試す前に素直に頼むべきだった

## 結果

| 指標 | 値 |
|---|---|
| 共通サンプル数 | 1788点(1秒刻み、30分間) |
| 相関係数 | 0.993 |
| 平均差(Electabuzz − powerk95) | -1.0 mHz |
| 標準偏差 | 4.7 mHz |

**周波数変動の「形」がほぼ完全に一致した。** verification.mdが要求する水準
(「乗算バイアスや実装差があっても変動の形は一致するはず」)を実データで満たすことを
確認できた——これでElectabuzzが本物の系統挙動を捉えていることの傍証が一つ増えた。

外れ値が5点(最大142mHz)あったが、精査すると別の発見に繋がった
(→ [2026-08-09-batch-boundary-jump-regression-cause.md](2026-08-09-batch-boundary-jump-regression-cause.md))。

## 次に何が可能になったか

外部照合の実施例ができたので、同じ手順(`/recent`取得 + powerk95手動CSV + JST秒join)を
テンプレート化すれば次回以降はもっと素早く回せる。W53SA氏との照合(生データ交換が必要)は
まだ未着手のまま。
