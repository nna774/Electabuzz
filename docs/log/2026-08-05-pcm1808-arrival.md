# PCM1808 が届いた — 無改造で使える。ついでに未決の問いが2つ潰れた

現物（両面写真）とデータシート（TI SLES177B, 2015-08 改訂）を突き合わせた結果。
**基板は無改造・ジャンパ無しでそのまま使える。**

## 現物

シルク `PCM1808` / `SKU:013325`、紫の CJMCU 系ブレイクアウト。
チップ刻印は `PCM1808 / BB S2A / C561`（`BB` = Burr-Brown）で TSSOP-14。

| 辺 | ピン（シルク順） |
|---|---|
| 上 | `BCK` `OUT` `LRC` `SCK` `GND` `3.3V` |
| 下 | `FMT` `MD1` `MD0` `GND` `3.3` `+5V` |
| 左 | `L IN` `GND` `R IN` |

- **`SCK` が SCKI（システムクロック入力）。** BCK と紛らわしいので取り違えるな
- デジタル4本には **100Ω の4連アレイ（刻印 `101`）が直列に入っている。** 終端済みで都合がよい
- 入力は電解コンデンサで **AC 結合**されている
- **缶発振器は載っておらず、載せるためのパッドも無い**（裏面は配線だけで部品ゼロ）

**発振器を外付けしないという [hardware.md](../hardware.md) の判断は、これで実質的に確定した。**
やるなら空中配線になる。**得るものが無い上に汚くなるので、なおさらやらない。**

## モードピンは開放でよい（これが一番効いた）

データシートの `7.3.5.1 Interface Mode` と Pin Functions の脚注から:

> Pins 10–12: MD0, MD1, FMT (Schmitt-trigger input, **with 50-kΩ typical pulldown resistor**, 5-V tolerant)

| MD1 | MD0 | インタフェースモード |
|---|---|---|
| **Low** | **Low** | **スレーブ (256/384/512 fS 自動判別)** |
| Low | High | マスタ (512 fS) |
| High | Low | マスタ (384 fS) |
| High | High | マスタ (256 fS) |

| FMT | フォーマット |
|---|---|
| **Low** | **I2S, 24-bit** |
| High | 左詰め, 24-bit |

**内部プルダウンがあるので、開放にしておけば `MD1=MD0=FMT=Low`** =
**スレーブモード + I2S 24bit** に落ちる。**これは本設計が欲しい構成そのものだ。**
ジャンパもはんだ付けも要らない。

GND へ落として確定させる手もある（下段ヘッダの `MD0` の隣が `GND` なので1本で済む）が、
**採らない。** データシートが明示している内部プルダウンで足り、
**配線が増えれば間違える余地も増える。**

> データシートは「MD1/MD0 は電源投入前に設定すること」と書いている。
> **プルダウンは電源投入の瞬間から効いているので、この条件は開放でも満たされる。**

## 構成の確定: PCM1808 スレーブ / ESP32 が I2S の完全マスタ

ESP32-S3 が **SCKI・BCK・LRCK の3本を出し**、`DOUT` を受ける。

**マスタモード（PCM1808 が SCKI を分周して BCK/LRCK を出す）も選べるが採らない。**
そちらは `fs = SCKI/256` の整数分周になる利点がある一方、ESP32 の I2S を slave RX で
回すことになる。**利点は `fs` の素性の良さだけで、それは ESP32 側でも
MCLK と LRCK が同じ PLL から出る以上すでに保証されている。**
踏み慣れた側を採る。

**ピン割り当て**（`GPIO 33〜37` は octal PSRAM、`26〜32` は flash、`43/44` はコンソール、
`19/20` は USB、`0/3/45/46` はストラップ。避けた結果）:

| PCM1808 | ESP32-S3 | 備考 |
|---|---|---|
| `SCK` (SCKI) | **GPIO 16** | I2S MCLK 出力 |
| `BCK` | **GPIO 17** | |
| `LRC` (LRCK) | **GPIO 18** | |
| `OUT` (DOUT) | **GPIO 15** | ESP32 側は入力 |
| `+5V` | 5V | **VCC はアナログ 4.5〜5.5V。3.3V では動かない** |
| `3.3V` | 3V3 | VDD（デジタル、2.7〜3.6V） |
| `GND` | GND | |
| `FMT` `MD1` `MD0` | **開放** | 内部プルダウンでスレーブ + I2S |

**電源が2系統要る点に注意しろ。** `VCC`（アナログ）は 5V 系で、モジュールに
レギュレータは載っていない。3.3V だけ与えても動かない。

## 潰れた問い1: AFE の分圧比

[open-questions.md](../open-questions.md) が「PCM1808 データシートのフルスケール入力
（VCC比で規定）から逆算する」としていた件。データシートの値は:

```
Analog input voltage, full scale (–0 dB)   VCC = 5 V   →  3 Vp-p   ( = 0.6 VCC )
```

**`VCC` は ESP32 の DevKit の `5V` ピンから取る。別電源は要らない。**
消費は `ICC` 8.6mA typ / `IDD` 5.9mA typ で USB 給電に対して誤差だ。
**そのピンの実測は 4.84V**（テスタ。USB VBUS からショットキー1個ぶん落ちた値）で、
規定の下端 4.5V に対して余裕がある。

**フルスケールは VCC に比例するので、公称 5V ではなくこの実測値で引く。**

```
フルスケール = 0.6 × 4.84 = 2.904 Vpp
目標          = 2.904 × 0.70 = 2.033 Vpp
分圧比        = 2.033 / 29.6 = 1/14.56
```

**ただし「70%」を precise な要求と読むな。** 効いている制約は**クリップしないこと**だけで、
超えれば位相推定が壊れる一方、**下に振れて困ることは実質ない**（24bit ADC で何万周期も積む
単一ビン DFT では SN 比が律速しない）。**60〜75% ならどれでもよく、迷ったら低い方へ振れ。**

E12 で組める例:

| R1 | R2 | 比 | FS 比 |
|---|---|---|---|
| 68k + 68k | 10k | 1/14.60 | 69.8% |
| 150k | 1k + 10k | 1/14.64 | 69.6% |
| 100k + 47k | 10k | 1/15.70 | 64.9% |

**引き出しにあるもので組めるのが一番いい。**
E24 の 11k を買い足すより、E12 の直列で済ませる方が正しい。

**ここから出た副次的な不変条件: 電源の取りかたと AFE の抵抗値は独立に決められない。**
フルスケールが `0.6 × VCC` で決まる以上、`VCC` を変えたら分圧比も引き直す必要がある。

**なお DMM が未入手なので、実配線後に壁電圧と二次側を測り直して詰める。**
上は実測2つ（VCC と二次側振幅）に基づく計算であって、AFE そのものの実測ではない。

> **モジュール側が既に AC 結合している**ので、AFE 側の `Vcc/2` バイアス網は
> **不要かもしれない**（モジュールが `VREF = 0.5 VCC` へ落としている可能性が高い）。
> **未確認。DMM が届いたらモジュール入力の DC 電位を測って決める。**
> 余計な回路を先に足すな。

## 潰れた問い2: 内蔵 HPF のコーナー周波数

同じく open-questions.md にあった「DIGITAL FILTER CHARACTERISTICS 表から
HPF コーナーの実数値」。**優先度低としていたが、データシートが手元にあるので拾った。**

```
HPF frequency response   –3 dB   →   0.019 fS / 1000
```

`fs = 48kHz` なら **0.912 Hz**。50Hz に対する位相進みは一次 HPF なので

```
arctan(0.912 / 50) = 1.045°   （時間にして 58 µs）
```

**結論は変わらない。** 定数位相なので周波数（位相の微分）には効かず、系統時刻偏差に対しても
58µs の固定オフセットにすぎない（測っているのは秒オーダーの量だ）。
**コーナーが `fs` に比例する**ため、`fs` が ppm 動けばこのオフセットも ppm 動くが、
58µs の百万分の一なので無視できる。**デジタルなので温度でも動かない。**

**この問いは閉じる。実測は不要。**

## ついでに拾った注意点

> Power-down and reset functions enabled by **halting SCKI, BCK, LRCK**.

**クロックを止めると PCM1808 はパワーダウン/リセットする。**
I2S を停止・再開する実装を書くときに効く。**セッション境界の扱い**
（→ [timebase.md](../timebase.md)）と同じ話で、**止めた区間を測れたことにするな。**

## 何が次に可能になったか

**AFE も GNSS も DMM も無しで、リスク10 の残り半分が埋められる。**

`fs` の測定に信号は要らない。I2S を配線してサンプルを数え、`NtpTimebase` の時間軸に対して
何 Hz で出ているかを見るだけだ。そして**比較すべき数字はもう手元にある**:

```
ESP32 の水晶     = +3.8873 ± 0.0055 ppm   （29.4時間の soak で確定、2026-08-05）
SCKI は ESP32 の MCLK  →  fs も同じ水晶から出る
∴ fs も +3.9 ppm 付近に出るはず。出なければ配線かクロック経路が想定と違う
```

**これで soak を止める理由ができた。** 配線に手を付ける時点で捕捉プロセスを落とす。
