# `fs` を測るファームを書いた — 水晶と `fs` を同じ NTP 標本から同時に出す

`firmware/src/main.cpp` をフェーズ1.5 v2 に書き換えた。ビルドは通っている
（`RAM 15.0% / Flash 10.9%`）。**まだ実機で走らせていない。**

## 何を測るか

**推定器を2本立てる。ティック源が違うだけで、食わせる NTP 標本は同一だ。**

| | ティック源 | 測っているもの |
|---|---|---|
| `gXtal` | `esp_timer`（µs） | **ESP32 の 40MHz 水晶**の実 ppm（従来の soak と同じ） |
| `gFs` | **I2S の累積フレーム数** | **`fs` そのもの**の実 ppm |

`NtpTimebase` は**ティック源を問わない**設計なので、これは同じクラスの2インスタンスで済む。
`NtpTimebase.h` の冒頭が最初からそう宣言していて、**1行も変えずに済んだ。**

**この2本を並べることが目的だ。** 構成上は SCKI が ESP32 の MCLK であり、MCLK も
`esp_timer` の systimer も同じ 40MHz 水晶に lock した PLL から出ている。
**したがって両者は各々の `residual` の範囲で一致しなければならない。**

```
gXtal = +3.8873 ± 0.0055 ppm   （2026-08-04〜05 の soak で確定済み）
gFs   = ?                       ← これが答え合わせ
```

**一致しなければ、配線かクロック経路が想定と違う。** それが分かることに値打ちがある。

## 落とし穴1: フレーム数だけでは PCM1808 が居ることを証明できない

**ESP32 が I2S のマスタなので、PCM1808 が1本も繋がっていなくても BCK/LRCK は出る。**
`i2s_read` はゼロのフレームを返し続け、フレーム数は何事もなく進み、
**`fs` は綺麗な値を出す。配線していなくても「測れた」ように見えるということだ。**

これは本レポの不変条件「測れなかった区間を測れたように見せるな」に真正面から抵触する。

対策として **L/R の振幅（`l_pp` / `r_pp`）を毎行に載せる。**
前回の報告以降のピーク差だ。**ここが 0 なら DOUT が死んでいる**（配線ミス、
電源未投入、モジュール不良のいずれか）。入力開放でも ADC のノイズフロアが出るので、
**生きていれば必ず 0 にはならない。**

## 落とし穴2: DMA が溢れると `fs` が静かに狂う

**読めなかったフレームは数えられない。** つまり溢れるとティック源が実時間に対して
遅れ、`fs` が実際より低く出る。**しかも何のエラーにもならない。**

3つ手を打った。

- **イベントキューを取って `I2S_EVENT_RX_Q_OVF` を数える**（`ovf` 列）。
  レガシー I2S ドライバは `i2s_driver_install` の第3・第4引数で渡せる
- **溢れを検出したら `gFs.reset()` する。** ティックが飛んだのだから線を繋いではいけない。
  水晶側（`gXtal`）は無関係なので巻き込まない
- **吸い出しを Core1 の専用タスクに置く。** WiFi と SNTP は Core0 で最大2秒ブロック
  しうるので、同じループに置くと確実に溢れる（`kNtpTimeoutMs = 2000`、
  DMA は 8×512 フレーム = 約85ms ぶんしか無い）

**この3つ目が本質だ。** 1つ目と2つ目は事故を見えるようにするだけで、防いではいない。

## 実装で決めたこと

**I2S はステレオで初期化した**（`I2S_CHANNEL_FMT_RIGHT_LEFT`）。R ch には何も
繋がっていないが、**ここだけが後戻りできない**（→ CLAUDE.md の不変条件）。

**`kFsNominalHz = 48000` は「要求」であって真値ではない。** `config.h` に
**使ってよい用途を3つだけ**と書いた: ①ドライバへの要求 ②回帰の初期値
③30ms 級の内挿。それ以外で「サンプルレート」として計算に使うな。

内挿について。SNTP 標本の時刻におけるフレーム数が要るが、スナップショットは
標本の**あと**にしか取れないので数十 ms ぶん巻き戻す必要がある。ここで公称値を
使っているが、**外挿区間が 30ms 級なので公称値が 1000ppm 狂っていても誤差は 30µs**
にしかならず、経路ノイズ（数 ms）のはるか下にある。**長期の傾きは実測のフレーム数が
決めており、ここは効かない。**

`rttTicks` はフレーム単位に直して食わせる（`NtpTimebase` が `rttTicks / 公称レート`
で µs に戻して足切りするため）。量子化は 1 フレーム = 20.8µs で、経路ノイズの
1/100 以下だから無害だ。

**I2S が一度も動いていないうちは `gFs` に食わせない。** `atUs` が 0 のまま外挿すると
起動からの経過ぶんを丸ごと足した嘘のフレーム数になる。**標本を1つ捨てる方がいい。**

## platformio の platform を版で pin した

`platform = espressif32` を **`espressif32@7.0.1`** にした。

**このコードはレガシーの `driver/i2s.h` に依存している。** 7.0.1 は Arduino core 2.0.x /
IDF 4.4 で、`driver/i2s_std.h` は存在しない。core 3.x（IDF 5）は別 API に移行しており、
**黙って上がるとビルドが落ちる。**

`batch-uplink` をタグで pin しているのと同じ理由だ（→ [batch-uplink.md](../batch-uplink.md)）。
**上げるときは I2S の書き直しとセットでやれ。**

## 次

配線して焼く。見るのは3つだ。

1. **`l_pp` / `r_pp` が 0 でないこと。** ここが 0 なら以降は全部無意味
2. **`ovf` が 0 のままであること。** 増えるなら吸い出しが追いついていない
3. **`fs_ppm` が `ppm`（水晶側）と一致すること。** これが本題

`fs_resid_ns` は水晶側と同じく数時間で 0.1ppm 級まで落ちるはずなので、
**一致・不一致を語るのは半日待ってからだ。**
