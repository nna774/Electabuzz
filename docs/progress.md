# 進捗ログ

- **2026-08-02: AC入力部が確定した。** Ideal Power DA-12-09 を入手し、
  100V/50Hz・周囲30℃・無負荷で1時間通電。**温度上昇は検出限界以下、唸りは無視できる水準、
  波形は素直な正弦波。** 三つの独立した物理量が「磁束は線形領域に余裕をもって収まる」で
  一致した。→ [hardware.md](hardware.md) の「現物検証ログ」
- **無負荷出力は想定より高い 29.6 Vpp / 約 10.5 VAC。** 分圧比を引き直す。
  絶対値の裏取りは DMM(HIOKI 3244-60、発注予定)の到着待ち。**分圧設計自体は待たなくてよい**
- **2026-08-02: フェーズ0(紙の調査)の主要2件が決着した。**
  - **東電PG/OCCTO は系統周波数を公開していない**(需給実績のみ)。当初の照合先は存在しなかった
  - **代わりに [powerk95](https://powerk95.net/50Hz/) を発見。** 東日本50Hz の周波数・RoCoF・
    **時差**を実時間公開し CSV 履歴もある。**外部照合先が確保できた**
  - **PCM1808 の HPF はデジタル**と確認。係数固定ゆえ熱ドリフトが原理的に起きず、
    リスク項目2はほぼ消滅した
- **目標イメージが確定した: powerk95 のようなサイト。** 実時間の周波数・RoCoF・時差、
  日次の最大/最小、閾値通知、履歴のリプレイ。ダッシュボード要件はここを参照する
- **友人 = W53SA 氏。[記事](https://www2.hatenadiary.jp/entry/2022/04/12/freqWatch)で構成が判明した。**
  東西の両方を測定。**ゼロクロス検出・時間基準なし・絶対確度 ±10ppm・時刻偏差は出していない**
  - **照合の位置づけが変わった。** 相手は無基準なので**絶対値の照合には使えない**。
    使えるのは**周波数変動の「形」とイベントの一致**。ΔTE は必ずランプになり、
    その傾きは**相手の水晶オフセットの実測値**として読む → [verification.md](verification.md)
  - **本設計の判断が二つ裏付けられた。** ①ACアダプタを絶縁センサに使う判断 ②**MCPWM
    input capture(= 本設計の方式B)に動いている先行例がある**。方式A が駄目でも退避先がある
  - **「時刻偏差を出していない」のは選択ではなく出せないから。** 無基準では 0.86秒/日 の
    偽の偏差が積算される。**GNSS 規正に投資する理由が実例として存在している**
- **2026-08-03: GNSS を待たずに走らせる方針が決まった。時間基準をプラグインにする。**
  - **`fs` を定数として書かない**設計にすれば、`NominalTimebase` / **`NtpTimebase`** /
    `PpsTimebase` の差し替えで済む。**GNSS 到着前は NTP 回帰で走る**
  - **NTP 時間基準の偽TE は 10〜90ms/日。** 系統時刻偏差の実変動(秒オーダー)より
    1〜2桁小さいので、**暫定どころか意味のあるデータが取れる**
  - **`NtpTimebase` は到着後も残す。** ①PPS 喪失時の holdover(リスク5 に初めて答えが付いた)
    ②`fs` の独立クロスチェック ③自分がどの水晶に乗っているかの実測
  - **wire format を今のうちに源非依存にした**(`tb_obs_count` / `tb_residual_ns` /
    `timebase_source` / `soc_temp_c`)。**予約領域から出したので PPS 到着時に
    ヘッダは1バイトも変わらない**
  - **後戻りできないのは R ch だけ。I2S は最初からステレオで初期化する**
  - **新発見: `fs` を決めているのが ESP32 の水晶なのか PCM1808 モジュールの缶発振器なのか
    未確定だった。** 缶発振器なら ±50〜100ppm、ESP32 MCLK なら分数分周器の誤差が数十ppm。
    **どちらにせよ「48000」は信用できない。フェーズ1.5 の実測で決める**
- **2026-08-03: 共有レポ名を `batch-uplink` に決定。** Python パッケージは `batch_uplink`。
  設計書唯一の未決事項が閉じた
- **2026-08-03: 手持ちは ESP32-S3 のみと確定。PCM1808 も要発注。**
  ただし **`NtpTimebase` は ADC 抜きで書けて実測もできる**(ティック源を `esp_timer` に
  差せばよい)。**着手可能タスクが2本になった** → 「次のセッションの開始点」
