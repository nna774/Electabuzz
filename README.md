# Electabuzz — 商用電力周波数モニタ

商用電力の周波数を常時測り、**系統時刻偏差**（グリッドの時計が標準時から何秒ずれているか）を
積算し続ける装置。設置先は 50Hz 地域（東日本）。

姉妹プロジェクト: [NamazuHaUrokoGaNai](https://github.com/nna774/NamazuHaUrokoGaNai)（家庭用地震計）。
送信基盤を共有ライブラリ `batch-uplink` として切り出して共用する。

> **状態: 設計フェーズ。** ハードウェアは AC入力部のみ確定・実測済み。コードは未着手。

## いま何をやるべきか

**ここから読め。** ハードウェア側は AC入力部が確定。**GNSS と PCM1808 は未入手だが、
それは進行の障害ではなくなった**(時間基準プラグイン方式。
[docs/timebase.md](docs/timebase.md) を読め)。

### 決着済みの前提 (2026-08-03)

- **共有レポ名は `batch-uplink` に決定。** Python パッケージ名は `batch_uplink`。
  GitHub `nna774` 配下。**設計書からプレースホルダは消えた**
- **手持ちハードウェアは ESP32-S3 のみ。** PCM1808 と GNSS は未入手(要発注)

### 着手可能なタスクは2つある。並行して進められる

**A. `batch-uplink` の切り出し → v1.0.0**(ハードウェア不要。下記「手順」)

**B. `NtpTimebase` を ESP32-S3 単体で先に書く**(PCM1808 を待たない)

**これが今回の発見だ。** 時間基準の回帰は「**単調増加するティック源** を NTP 時刻に
回帰する」処理であり、**そのティックが I2S のサンプル数か `esp_timer` の µs かを
問わない。** だから ADC が無くても本体を書けて、しかも捨て仕事にならない。

- ティック源をインターフェイスにしておけば、`esp_timer` → I2S サンプル数 → PPS の
  差し替えが全部同じ形になる
- **今日から数日走らせるだけで、手元の ESP32-S3 の水晶の実 ppm と温度相関が取れる。**
  これはリスク10(`fs` を決めているクロックの出自)の**片方の候補の実測値**そのものだ。
  PCM1808 が届いた日に、缶発振器と比較する基準が既に手元にある
- 測定専用 SNTP クライアント(システム時刻を触らない)・RTT フィルタ・回帰・
  残差の 1σ 算出は**全部この段階で書き切れて、テストも書ける**

**【B を先にやれ】と言うつもりはない。A は地震計を巻き込むリスクを消す作業なので
優先度は依然 A が上だ。** ただし A は実機焼き直しの検証待ちが入るので、
**その待ち時間に B を走らせておくのが最も詰まらない順序になる。**

### 手順 ([docs/batch-uplink.md](docs/batch-uplink.md) 「切り出しの順序」節の再掲。絶対に順序を守れ)

1. **共有レポを作り、対象を一文字も変えずに移す。`Batch` の一般化はまだしない**
   - C++: `lib/Batch/`(+`WireFormat.h`)、`lib/Uploader/`(+`HmacSha256.h`)、`lib/TimeSync/`
   - Python: `auth.py`、`devices.py`、`notify.py`、`s3util.py`(prefix を引数化)
   - **入れないもの**: `lib/Display/`(震度クラス字形)、`events.py`(地震に染まっている)、
     `wire.py` / `store.py` / `detect_core.py` / `quicklook.py`(numpy 依存 + 地震専用)
   - `library.json`(deps: ArduinoJson)と `pyproject.toml` を置く
2. NamazuHaUrokoGaNai を **v1.0.0 に pin**(`lib_deps ...#v1.0.0` / `requirements.txt @v1.0.0`)
   - **`build_lambda.sh` の pip は必ず2回に分けること。** `--platform` は
     `--only-binary=:all:` を要求し、`git+` と両立しない
3. **`pytest lambda/tests` `pytest tools/tests` が緑 + `[env:esp32dev]` を実機に焼いて
   バッチが従来通り着弾すること。** これが唯一の検証点
4. 通ったら **v1.0.0 をタグで固定。地震計はもうここから動かさない**
5. その後で `Batch` のレコード長可変化を入れて **v1.1.0**
6. Electabuzz は v1.1.0 を参照。地震計は v1.0.0 のまま**一切触らない**

> **タグで pin しろ。ブランチ追従にするな。** これが独立レポ構成における唯一の落とし穴。
> `#main` にすると Electabuzz のための変更が地震計の次回ビルドで黙って混入し、
> **結合が不可視になる**。単一レポより悪い壊れ方をする。


## 要約

**作るもの。** 商用電力の周波数を常時測り、さらに**系統時刻偏差**——グリッドの時計が
標準時から何秒ずれているか——を積算し続ける装置。設置先は 50Hz 地域。

**難所は1つだけ。** 位相推定はサンプル列を時間軸として使うので、**ADCのサンプルレートの
誤差がそのまま測定値の誤差になる。** ESP32 の水晶 ±20ppm は、積算すると
**1日あたり1.7秒の偽の時刻偏差**を生む。実際の系統時刻偏差の全変動幅が数秒なのだから、
これは誤差ではなく破壊だ。**ここを解けるかどうかが全てで、他は全部その後の話。**

**解き方(この設計の核心)。** PCM1808 は**ステレオ**ADCである。
L に商用波形、**R に GPS の 1PPS** を入れる。すると信号と時間基準が
**同一のサンプルクロックで測られる**ので、クロック誤差が両方に共通に乗り、
比を取った時点で**一次で相殺する**。熱ドリフトは完全に消える。
結果として**水晶の質にほとんど依存しない測定器**になり、TCXO も GPSDO も要らない。

**保存するもの。** 周波数ではなく**累積位相**。周波数はその微分、時刻偏差はその差分として
後から導出できる。微分値だけ保存すると欠測のたびに積分が壊れて二度と復元できない。

**買うもの(段階1で 12,000〜18,000円)。** ESP32-S3 + PCM1808 +
**安価な u-blox ブレイクアウト ×2**(1台は本番、1台は校正の基準源) +
**トランス式AC出力アダプタ Ideal Power 77DA-12-09**。アダプタはコンセントに挿すだけで
完全絶縁——**商用電源に一切配線しない**のが安全設計の要。

**金をかけるべきは受信機ではなくアンテナだ。** アクティブアンテナを窓際か屋外に引け。
タイミング用の NEO-M8T($100前後)は**まだ買うな**。要るかどうかは家の空の見え方で決まり、
それは段階1の実測で分かる。**未測定のリスクに保険を先払いするのは順序が逆だ。**

**ソフトとインフラ。** NamazuHaUrokoGaNai の送信基盤(リングバッファ・LittleFS退避・
**決定論的S3キーによる冪等バックフィル**)は既に欠測ゼロを解いているのでそのまま使う。
ただし共通部分を**バージョン付きの独立レポジトリに切り出してタグで pin** し、
**AWSスタックも分離**する。稼働中の地震計を壊しえない構成にする。

**確度の担保。** 二重測定はしない(Pi は母艦の代替案であって第2系ではない)。
代わりに **GNSS の TIMEPULSE2 を 50.000000Hz に設定して L ch に入れ、本番と同じ信号経路で
既知の GNSS 同期信号を測る**。関数発生器より確実で、トレーサビリティが GNSS まで繋がる。

**別件の NTP サーバとの共用。** 共用するのは**アンテナだけ**。受信機は2台買う。

**貫く一線。** 測れなかった区間を測れたように見せない。セッション境界で線を繋がない。

## Context: なぜ作るのか

家庭に設置する商用電力周波数の常時測定装置を作る。現在値表示に留まらず
**系統時刻偏差(accumulated time error)の積算**まで含む。すなわち「グリッドの時計が
標準時に対して何秒ずれているか」を連続追跡する。
**設置先は 50Hz 地域(東日本)。** コードは 50/60Hz 両対応・自動判別で作るが、
ハードウェアの選定と検証は 50Hz を前提に詰める。
目標確度 ±1mHz 以下、分解能 0.1mHz 級。保存先は家の外部(AWS)。

**既存資産がある。** `../NamazuHaUrokoGaNai` — IIS3DHHC + ESP32 で 100Hz の加速度を
測り、S3 をデータストアとして気象庁の計測震度を評価する家庭用地震計。実機稼働中。

この設計書はゼロから構成を考えるものではなく、**実コードを読んだ上で「何がそのまま
使え、何を一般化し、何が本質的に足りないか」を切り分ける**ものである。

結論。**パイプラインの大半はそのまま使える。本質的な差分は3点。**

1. **時間基準** — 既存の NTP + 公称サンプルレート前提では周波数測定が成立しない
2. **retention** — 累積量なので `raw/` の90日expiryとは別に永久保存層が要る
3. **ロールアップ** — 1年連続グラフのための階層的ダウンサンプル(既存には概念がない)

認証・転送・欠測耐性・イベント状態機械・通知・死活監視・IaC はほぼ無改造で流用できる。
